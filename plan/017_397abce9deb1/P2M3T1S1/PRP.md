## Why

- **PRD §21.2 distribution surface + external_deps.md §5**: Nix flakes are a first-class install
  channel for the developer-tooling audience. The flake lives in-repo (no external repo/secret), powers
  `nix run`/`nix profile install`/devbox/nix-shell, and is the only distribution surface that is also a
  local-dev environment.
- **Parity with the released binary**: the flake builds the SAME artifact goreleaser ships
  (`cmd/stagecoach`, `CGO_ENABLED=0`, module `github.com/dabstractor/stagecoach`), so `nix run` and the
  GitHub-Release binary are behaviorally identical. goreleaser stays the canonical release path (real
  version strings via ldflags); the flake is the reproducible source-build surface.
- **CI keeps it honest**: a stale `vendorHash` is the #1 flake breakage (every `go get`/`go mod tidy`
  that changes go.sum invalidates it). A `nix flake check` job surfaces the new hash immediately — the
  failure message literally prints the value to paste — so the Nix surface cannot silently rot.

### Known Gotchas of our codebase & Library Quirks

```nix
# GOTCHA 1 (vendorHash is the current arg; vendorSha256 is deprecated). buildGoModule's argument is
#   `vendorHash` (SRI sha256). `vendorSha256` (base32) still works but is deprecated. Use vendorHash.
#   The placeholder is `lib.fakeHash` (= "sha256-AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA="), NOT
#   `lib.fakeSha256` (base32 "0000...="). external_deps.md §5 names vendorHash explicitly.

# GOTCHA 2 (the REAL vendorHash must be pasted before merge; lib.fakeHash never builds). The flake
#   ships with lib.fakeHash ONLY while iterating. To get the real hash: run `nix build`, read the
#   "got: sha256-..." line from the fixed-output mismatch error, paste it into vendorHash, re-run.
#   CI's `nix flake check` will FAIL on lib.fakeHash too (it cannot build) → so the real hash MUST be
#   committed. If Nix is unavailable locally, ship lib.fakeHash + let CI's first run print the got-hash;
#   paste it in a follow-up commit. (Document this in docs/packaging.md.)

# GOTCHA 3 (the nix-built binary reports version "dev"). The flake does NOT pass goreleaser's
#   `-X main.version={{.Version}}` ldflags, and Go's VCS embedding (vcs.revision) is unavailable in
#   the nix sandbox (source is copied to the store WITHOUT .git). So `stagecoach --version` shows
#   "dev" (resolveVersion() returns "dev" with no VCS info). goreleaser remains the canonical release
#   path for real version strings. Do NOT try to replicate goreleaser's ldflags in the flake (the
#   contract does not require it; the flake's `version` is the DERIVATION name, not the binary's).

# GOTCHA 4 (CGO_ENABLED=0 via env). The modern buildGoModule idiom is `env = { CGO_ENABLED = 0; }`
#   (nixpkgs moved env to the `env` attr). Bare top-level `CGO_ENABLED = 0;` also works, but use the
#   `env.CGO_ENABLED` form. This matches .goreleaser.yaml + ci.yml's static-build invariant.

# GOTCHA 5 (commit flake.lock; do NOT gitignore it). stagecoach is an APPLICATION, so flake.lock is
#   COMMITTED (pins nixpkgs for reproducible `nix flake check` in CI). Only LIBRARIES leave
#   flake.lock un-committed. .gitignore gets result, result-*, .direnv — but NOT flake.lock.

# GOTCHA 6 (eachSystem via genAttrs — no flake-utils). Use nixpkgs.lib.genAttrs over the 4 systems;
#   do NOT add numtide/flake-utils as an input (one fewer dependency). See findings.md §6.

# GOTCHA 7 (nix flake check builds the current system; older Nix tried all systems). On modern Nix
#   (2.21+, which install-nix-action's 2025 default is), `nix flake check` defaults to the CURRENT
#   system (x86_64-linux on the ubuntu runner) → builds the linux package → a stale vendorHash fails
#   with the got-hash. If the impl observes darwin/aarch64 build attempts failing (older Nix), fall
#   back to `nix build .#default --print-build-logs` (builds only the local system). See findings.md §5.

# GOTCHA 8 (go 1.22 directive needs a current nixpkgs). go.mod says go 1.22. nixos-unstable and
#   nixos-24.11+ ship Go >= 1.22. The flake's inputs.nixpkgs.url = github:NixOS/nixpkgs/nixos-unstable
#   satisfies this. FR-D5: at impl, verify the resolved nixpkgs (flake.lock) provides Go >= 1.22
#   (`nix flake metadata` / `nix build .#default` will fail loudly if not).

# GOTCHA 9 (no vendor/ dir → no proxyVendor). The repo has no vendor/ directory; buildGoModule's
#   default go-modules FOD fetches deps from the module proxy. Do NOT set proxyVendor or modHash.
```

## Anti-Patterns to Avoid

- ❌ Don't ship `lib.fakeHash` to main — it NEVER builds (CI `nix flake check` fails too). Obtain the real
  hash via `nix build`, paste the got-hash. (Fallback only if no local Nix: ship fakeHash + paste the
  got-hash CI prints on first run.) See Gotcha 2.
- ❌ Don't use `vendorSha256` (deprecated alias) — use `vendorHash`. Don't use `lib.fakeSha256` (base32)
  for the placeholder — use `lib.fakeHash` (SRI). See Gotcha 1.
- ❌ Don't replicate goreleaser's `-X main.version` ldflags in the flake — the contract does not require
  it; the nix binary reports "dev" by design (no .git in sandbox). goreleaser owns version strings. See Gotcha 3.
- ❌ Don't add `flake-utils` as an input — use `nixpkgs.lib.genAttrs` for eachSystem (one fewer dependency). See Gotcha 6.
- ❌ Don't gitignore `flake.lock` — stagecoach is an APPLICATION; commit flake.lock for reproducible CI.
  Only libraries leave it un-committed. See Gotcha 5.
- ❌ Don't add a `nix.conf`/`experimental-features` step to CI — install-nix-action enables flakes BY
  DEFAULT. A redundant enable step is dead code.
- ❌ Don't add cachix for v3.0 — the contract DECISION is to skip it (small Go static binary; add later).
- ❌ Don't set `continue-on-error: true` on the nix job — a stale vendorHash MUST fail (so the nix error
  surfaces the got-hash). The whole point of the CI job is to keep vendorHash current.
- ❌ Don't set `CGO_ENABLED` as a bare top-level attr "the old way" without knowing — prefer the modern
  `env.CGO_ENABLED = 0;` (both work, but `env` is current). See Gotcha 4.
- ❌ Don't edit release.yml, npm/*, .goreleaser.yaml, any Go file, or the 5 existing ci.yml jobs — this
  task adds ONE ci.yml job + flake.nix + flake.lock + .gitignore entries + a docs/packaging.md section.
- ❌ Don't recreate docs/packaging.md if it already exists (WinGet section from P2.M2.T1.S1) — APPEND the
  Nix section. The two sections coexist. If it doesn't exist, create with a neutral intro + the Nix section.
- ❌ Don't forget FR-D5 — re-verify the install-nix-action version pin, that the locked nixpkgs provides
  Go >= 1.22, and the `nix flake check` current-system behavior at impl; record the date.
